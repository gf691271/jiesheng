# 接声音频拆分设计

## 目标

在保留现有多文件合并流程的同时，增加一个完全离线的单文件拆分流程：用户手动输入 2–20 个秒级切点，选择一次目标文件夹，应用将一个音频拆成 3–21 个 M4A 文件。

## 用户流程

1. 主页面增加“拆分音频”入口，进入独立拆分页面；现有合并队列和导出行为不变。
2. 拆分页面通过 Android 系统文档选择器选择一个 `audio/*` 文件，不申请新的媒体权限。
3. 页面显示完整文件名和总时长，不提供播放、试听或波形。
4. 页面默认提供两个切点输入框，并允许增加或删除到 2–20 个。
5. 切点接受 `分:秒` 或 `时:分:秒`，精确到整秒。提交时按时间升序排列。
6. 所有切点有效后，用户点击“拆分并导出”，选择一次目标文件夹。
7. N 个切点生成 N+1 个文件，名称为 `原文件名_01.m4a`、`原文件名_02.m4a`，依此类推。原文件始终保持不变。

## 输入与校验

- 切点数量必须为 2–20 个。
- 每个切点必须能够完整解析，秒和分字段必须位于 `00`–`59`；小时可大于 23。
- 切点必须大于 `00:00`，并严格小于源音频总时长。
- 不允许重复切点。输入顺序不影响结果，应用按时间自动排序后生成区间。
- 任一输入无效时不打开目标文件夹选择器，并在对应输入项或页面状态中给出中文错误。
- 源文件无法读取、时长无效或不含音轨时不进入可导出状态。

## 页面与状态

新增 `SplitActivity` 和 `SplitViewModel`，避免把单文件拆分状态混入 `MainViewModel` 的合并队列。

拆分页面包含：

- 返回按钮和“拆分音频”标题；
- 选择或更换源音频按钮；
- 源文件名与总时长；
- 2–20 行切点输入项，每行可删除；
- “添加切点”按钮；
- “拆分并导出”主按钮；
- 导出进度、取消按钮和结果提示。

读取源文件、选择目标文件夹和导出期间冻结源文件与切点编辑。状态机明确区分空闲、读取源文件、选择目标文件夹、拆分中、完成和失败。

## 拆分模型与 Media3

新增纯 Kotlin 拆分模型：

- `SplitPointParser` 将文本转换为毫秒；
- `SplitPlan` 校验并排序切点，生成覆盖 `[0, duration)` 的连续 `SplitSegment(startMs, endMs)`；
- `SplitExportNames` 从源文件名生成带两位序号的 M4A 名称。

新增 `AudioSplitEngine` 边界及 Media3 实现。每个区间使用 `MediaItem.ClippingConfiguration` 指定起止毫秒，以 Media3 Transformer 转码为单轨 AAC/M4A。拆分按区间顺序串行执行，避免同时运行多个 Transformer 并限制临时磁盘占用。

Media3 仍使用项目已锁定的 `androidx.media3:media3-transformer:1.9.4`，不引入 FFmpeg、播放器、波形库、网络权限或后台服务。

## 存储、命名与进度

- 目标使用 Storage Access Framework 的目录选择器；应用只写入用户明确选择的目录。
- 每段先写到应用缓存中的单个临时 M4A，复制到目标文档后立即删除临时文件，再处理下一段。
- 目标 provider 如遇同名文件，可按其标准行为生成不冲突名称；应用不覆盖既有文件。
- 总进度由“已完成段数 + 当前段进度”计算。
- 成功时显示实际导出的段数和目标文件夹。

## 取消与错误处理

- 用户取消时终止当前 Transformer，删除当前临时文件，并尝试删除本次任务已经创建的目标文档。
- 任一段转换、创建文档或复制失败时停止后续处理，并对本次任务已创建的目标文档执行相同的尽力回滚。
- 如果 provider 不支持删除，提示可能保留的文件数量，避免把部分成功误报为完整成功。
- 屏幕旋转由 Activity 的 `configChanges` 保持当前实例，避免导出回调连接到旧页面；进程被系统终止时不承诺恢复未完成任务。

## 测试与验收

### 单元测试

- 解析 `01:23`、`01:02:03` 和大于 23 小时的合法输入。
- 拒绝空值、字段缺失、负数、秒或分超过 59、带小数和多余字符。
- 拒绝少于 2 个、超过 20 个、重复、零点和超出总时长的切点。
- 将乱序切点转换为连续、升序、首尾完整覆盖的 3–21 个区间。
- 输出名称去除原扩展名，并使用 `_01.m4a` 到 `_21.m4a`。
- ViewModel 在读取、选择目录和导出期间冻结编辑，并正确计算整体进度。

### Android 测试

- Media3 对真实音频资产的多个区间分别生成只有一个音轨的 M4A，并验证各段时长处于编码容差内。
- 拆分页面可选择源文件、显示文件名和时长、增减切点，并仅在输入有效时启用导出。
- 取消或失败不会修改源文件，当前临时文件会被删除。

### 发布验收

- 运行全部单元测试、API 35 Android 测试、release lint 和 release 构建。
- 在 API 35 模拟器手工输入乱序切点，选择一次目标文件夹，确认输出数量、顺序、名称和可播放时长。
- 版本升级为 `0.3.0`（versionCode `4`），生成可安装 APK 和 SHA-256 校验文件。
- 若正式签名凭据在本机构建环境可用，使用现有 `jiesheng` 签名；否则明确交付 debug 签名 APK，不把任何密钥写入仓库或日志。

## 非目标

- 不提供试听、播放控制、波形、毫秒级切点、拖动时间轴或自动静音检测。
- 不支持选择视频作为拆分源。
- 不支持只导出部分区间、修改片段名称、淡入淡出、音量调整或多轨混音。
- 不改变现有合并功能的 2–20 个来源上限、排序、输入来源或导出格式。
